---

Нужно найти вероятность того, что при броске трёх 10‑гранных костей (каждая со значениями от 1 до 10) **ровно два значения совпадут**, а третье будет отличаться.

## Шаг 1: общее число исходов

Каждая кость может выпасть 10 способами, всего костей — 3.  
Общее число равновероятных исходов:

N = 10 \times 10 \times 10 = 10^3 = 1000.


---

## Шаг 2: число благоприятных исходов (ровно два одинаковых)

Чтобы было ровно два одинаковых значения, нужно:

1. **Выбрать значение, которое повторится дважды.**  
   Вариантов: 10 (любое число от 1 до 10).

2. **Выбрать, какие две из трёх костей покажут это значение.**  
   Число способов выбрать 2 кости из 3: \binom{3}{2} = 3.

3. **Выбрать значение для оставшейся кости.**  
   Оно должно отличаться от повторяющегося, поэтому остаётся 9 вариантов.

Итого число благоприятных исходов:

M = 10 \times 3 \times 9 = 270.


---

## Шаг 3: вероятность

Вероятность — это отношение благоприятных исходов к общему числу:

P = \frac{M}{N} = \frac{270}{1000} = 0{,}27.


То есть вероятность равна **27 %**.

---

Метод Монте‑Карло — это как «много раз бросить кости в симуляции» и посмотреть, как часто случается нужный исход. Чем больше бросков (итераций), тем точнее оценка — это работает закон больших чисел.

## Базовая идея

1. **Симулируем бросок** n костей с m гранями.
2. **Проверяем условие** (например, «есть значение, выпавшее хотя бы k раз»).
3. **Повторяем** это N раз (например, 10^6).
4. **Считаем долю** успешных исходов — это и есть оценка вероятности.

## Реализация на TypeScript

```ts
/** Бросает n костей с m гранями (значения от 1 до m) */
function rollDice(n: number, m: number): number[] {
  return Array.from({ length: n }, () => Math.floor(Math.random() * m) + 1);
}

/**
 * Проверяет, есть ли значение, которое выпало хотя бы k раз
 */
function hasAtLeastKMatches(values: number[], k: number): boolean {
  const counts = new Map<number, number>();
  for (const v of values) {
    counts.set(v, (counts.get(v) ?? 0) + 1);
  }
  for (const c of counts.values()) {
    if (c >= k) return true;
  }
  return false;
}

/**
 * Считает вероятность методом Монте‑Карло
 */
function monteCarloProbability(
  n: number,
  m: number,
  k: number,
  trials: number
): number {
  let success = 0;
  for (let i = 0; i < trials; i++) {
    const roll = rollDice(n, m);
    if (hasAtLeastKMatches(roll, k)) {
      success++;
    }
  }
  return success / trials;
}

// Пример: 10 костей, 300 граней, хотим вероятность хотя бы 3 совпадений
const diceCount = 10;
const faces = 300;
const k = 3;
const trials = 1_000_000;

const prob = monteCarloProbability(diceCount, faces, k, trials);
console.log(`P(хотя бы {k} совпадений) ≈ {prob.toFixed(4)}`);
```

## Как адаптировать под «ровно k совпадений»

Если нужно не «хотя бы k», а **ровно одна группа размера k** (и нет групп больше k, и других групп размера k тоже нет — зависит от точной формулировки), меняем проверку:

```ts
function hasExactlyOneGroupOfSizeK(values: number[], k: number): boolean {
  const counts = new Map<number, number>();
  for (const v of values) {
    counts.set(v, (counts.get(v) ?? 0) + 1);
  }

  let groupsOfSizeK = 0;
  let anyLarger = false;

  for (const c of counts.values()) {
    if (c === k) groupsOfSizeK++;
    if (c > k) anyLarger = true;
  }

  // Ровно одна группа размера k и нет групп больше k
  return groupsOfSizeK === 1 && !anyLarger;
}
```

И вызываем:

```ts
const probExactlyOneTriple = monteCarloProbabilityCustom(
  diceCount,
  faces,
  3,
  1_000_000,
  hasExactlyOneGroupOfSizeK
);
```

(Для этого понадобится небольшая модификация `monteCarloProbability`, чтобы передавать свою функцию проверки.)

## Важные практические моменты

- **Точность.** При 10^6 испытаниях стандартная ошибка порядка \sqrt{p(1-p)/N} \approx 0{,}001 (0,1 %). Если нужна точность 0,01 %, бери 10^8 итераций, но это дольше.
- **Производительность.** Для 10^7 итераций в Node.js это обычно секунды. Если нужно быстрее — можно:
    - использовать Web Workers / кластер,
    - распараллелить на несколько ядер (учитывая твой интерес к параллельным вычислениям),
    - или вынести горячий цикл в нативный аддон/Wasm.
- **Воспроизводимость.** Для отладки полезно фиксировать seed генератора случайных чисел. В стандартном `Math.random()` seed не задаётся, но можно подключить библиотеку типа `seedrandom`:

  ```ts
  import seedrandom from 'seedrandom';

  const rng = seedrandom('my-seed');
  function rand() { return rng(); } // вместо Math.random()
  ```

## Сравнение с аналитическим расчётом

- Для «хотя бы одно совпадение» (т.е. k=2) аналитически удобно через дополнение: 1 - P(\text{все разные}).
- Для k=3,4,\dots аналитический расчёт быстро усложняется из‑за комбинаторных случаев (одна тройка, две тройки, тройка+пара и т.д.).
- Метод Монте‑Карло остаётся одинаково простым для любого k, зато даёт **приближение**, а не точное значение.

## Примерные оценки для 10 костей и 300 граней

На основе симуляций (и теории) можно ожидать примерно такие значения:

- P(\text{хотя бы } 2) \approx 13{,}9\%
- P(\text{хотя бы } 3) \approx 0{,}5–1\% (точное значение зависит от симуляции)
- P(\text{хотя бы } 4) — уже очень мало, доли процента.

Это логично: при большом числе граней редкие события (тройки, четвёрки) случаются редко.

## Связь с твоими интересами к алгоритмам и тестированию

- Такой код легко превратить в **автотест**: запустить симуляцию, сравнить с ожидаемым диапазоном вероятности и падать, если расхождение слишком большое.
- Можно использовать **Vitest** (раз ты его изучаешь) для проверки:
    - что функция `rollDice` действительно возвращает числа в диапазоне;
    - что при очень большом числе испытаний оценка близка к аналитическому значению (для простых случаев).
- Это хороший пример **стохастического тестирования**: вместо детерминированных проверок мы проверяем статистические свойства.
