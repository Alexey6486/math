### Взаимоотношения между таблицами
Существует три типа связей между таблицами:  
- один ко многим,  
- один к одному,  
- многие ко многим.   

### Один ко многим
```
Две таблицы А и В связаны связью «один ко многим», если: 
- одной строке из таблицы А может соответствовать множество строк из таблицы В,
- при этом каждой строке из таблицы В может соответствовать только одна строка из таблицы А.
```
Пример, таблица shipments и таблица clients.  
В одной строке таблицы shipments указан один клиент - одна строка этой таблицы ссылается на одну строку в таблице clients. 
А в таблице clients, одна строка - т.е. клиент - может встречаться во многих строках таблицы shipments.

Т.о. связь таблицы clients и shipments - один ко многим.  
И наоборот, таблица shipments к таблице clients - многие к одному.

Таблица clients называется **родительской**, а shipments — **дочерней**.  
Дочерняя таблица зависит от родительской и содержит ссылку на неё.  

### Один к одному
```
Таблицы А и В связаны связью «один к одному», если: 
- одной строке из таблицы А соответствует не больше одной строки из таблицы В
- и одной строке из таблицы В соответствует только одна строка из таблицы А.
```

### Многие ко многим
```
Таблицы А и В связаны связью «многие ко многим», если:
- одной строке из таблицы А может соответствовать множество строк из таблицы В
- и любой строке из таблицы В может соответствовать множество строк из таблицы А.
```
Чтобы организовать связь «многие ко многим», необходимо создать промежуточную таблицу.  

### Внешние ключи
Чтобы следить за целостностью данных, необходимо «связать» две таблицы (родительскую и дочернюю) так,  
чтобы при изменении, удалении или обновлении данных в родительской таблице учитывалось влияние этих  
операций на дочернюю. Для этого одно из полей дочерней таблицы помечают как внешний ключ (FK — от англ. Foreign Key).  
Внешний ключ накладывает ограничения: мы не можем свободно изменять, удалять или обновлять данные в  
родительской таблице, не принимая во внимание, как это отразится на дочерней.  
Такое ограничение называется ограничением внешнего ключа. В дальнейшем мы будем использовать понятия «внешний ключ» и  
«ограничение внешнего ключа» как эквивалентные.  

<столбец_дочерней_таблицы> <тип_столбца> **REFERENCES** <имя_родительской_таблицы> (<столбец_родительской таблицы>)  

```
CREATE TABLE shipments (
    id integer PRIMARY KEY,
    datetime timestamp,
    freight text,
    sender_id integer REFERENCES clients (id),
    receiver_id integer REFERENCES clients (id),
    speed_id integer REFERENCES speeds (id)
)

Обратите внимание: если при создании дочерней таблицы мы добавляем внешний ключ,
родительская таблица уже должна существовать. В нашем случае при объявлении таблицы shipments
мы ссылаемся на clients и speeds, следовательно, их нужно создать раньше.
```

Можно также добавить внешний ключ в уже существующую таблицу, для этого используем команду **ALTER TABLE**:  
```
ALTER TABLE shipments ADD FOREIGN KEY (sender_id) REFERENCES clients (id)
```

Иногда нужно задать внешнему ключу пользовательское имя — например, для совместимости с уже существующим в компании ПО.  
Для этого перед REFERENCES добавляется ключевое слово CONSTRAINT <имя_внешнего_ключа>.  
Например, назовём внешние ключи по шаблону fk_<имя_дочерней_таблицы>_<имя_родительской таблицы>_<имя_столбца>:  

```
CREATE TABLE shipments (
    id integer PRIMARY KEY,
    datetime timestamp,
    freight text,
    sender_id integer CONSTRAINT fk_shipments_clients_sender_id REFERENCES clients,
    receiver_id integer CONSTRAINT fk_shipments_clients_receiver_id REFERENCES clients,
    speed_id integer CONSTRAINT fk_shipments_speed_speed_id REFERENCES speeds
)
```

### Поведение при удалении
Когда внешний ключ создан, можно указать, что делать при попытке удаления или обновления данных в родительской таблице.  
При этом указывают операцию, при которой происходит проверка:  
- действия при удалении задают с помощью ON DELETE;  
- действия при обновлении задают с помощью ON UPDATE.  

После ключевого слова ON DELETE нужно указать, что делать при удалении строки в родительской таблице.  
Вариантов несколько:  
- RESTRICT — запрещаем удалять строку в родительской таблице.  
- CASCADE — если удаляем строку из родительской таблицы, то удаляем и связанные с ней строки дочерней таблицы.  
- NO ACTION — похоже на RESTRICT, но RESTRICT сразу запрещает все удаления и обновления,  
а NO ACTION «откладывает» проверку до конца транзакции. Транзакция — это группа операций,  
которые или выполняются все вместе, или не выполняются вообще — например, если в одной из них произошла ошибка.  
Удаление строки родительской таблицы может происходить в начале или середине транзакции.  
Подробно вы познакомитесь с транзакциями в следующем модуле.  
- SET NULL — проставляем в соответствующих ячейках дочерней таблицы значения NULL.  
- SET DEFAULT — проставляем в соответствующих ячейках дочерней таблице значения по умолчанию.  

Если внешний ключ составной, то после SET NULL и SET DEFAULT можно указать конкретный столбец, для которого будет проставлено значение по умолчанию либо NULL. Подробнее об этом читайте в документации.  

По умолчанию всегда используется стратегия NO ACTION.  

```
CREATE TABLE shipments (
    id integer PRIMARY KEY,
    datetime timestamp,
    freight text,
    sender_id integer REFERENCES clients ON DELETE RESTRICT,
    receiver_id integer REFERENCES clients ON DELETE RESTRICT,
    speed_id integer REFERENCES speeds ON DELETE RESTRICT
)
```

### Удаление внешнего ключа
```
-- удаляем внешний ключ
ALTER TABLE routes DROP CONSTRAINT routes_station_id_fkey;
-- добавляем новый внешний ключ с действием ON DELETE CASCADE
ALTER TABLE routes ADD FOREIGN KEY (station_id) REFERENCES stations ON DELETE CASCADE;
-- пробуем удалить строку из stations
DELETE FROM stations WHERE id = 3;
-- проверяем, что строки из routes также удалились
SELECT * FROM routes 
```

### Удаление и очистка таблиц, связанных внешними ключами
```
DROP TABLE stations CASCADE;

TRUNCATE TABLE clients CASCADE;
```
